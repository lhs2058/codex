# 기존 SMD 파일 기준정보·세부 실적 통합 등록 설계

## 목적

기존 SMD 원본 파일을 수정하지 않고 업로드하여 모델, 라인, 조, 시간대, 비가동 사유와 ST 후보를 검토·승인한 뒤 생산·품질·불량·비가동 세부 실적과 함께 원자적으로 등록한다.

지원 원본은 현재 보존된 다음 다섯 종류다.

- AOI 월간 품질 파일
- SPI 월간 품질 파일
- ICT 월간 품질 파일
- X-ray 월간 품질 파일
- SMD 공정별 시간대 생산 파일

기존 전용 파서가 대조하는 기준 행수는 AOI 239행, SPI 271행, ICT 90행, X-ray 262행, 실제 교대 생산 상세 9,658행(DAY 4,953행, NIGHT 4,705행)이다. 생산 원본의 `Total` 집계 구간 5,050행은 다음 DAY/NIGHT 교대가 시작될 때까지 상세 및 CAPA/ST 근거에서 제외하며, 원본 파일과 체크섬은 변경하지 않는다.

## 역할과 승인

- 작업자는 원본 파일을 업로드하고 분석 결과, 기준정보 후보, 세부 실적 및 오류를 조회할 수 있다.
- 관리자만 기준정보와 ST 후보를 선택·수정·승인하고 중복 실적의 교체 여부를 결정할 수 있다.
- 기준정보는 자동 확정하지 않는다. 관리자가 최종 반영을 실행해야 생성된다.
- 기존 기준정보를 자동으로 덮어쓰거나 비활성화하지 않는다.

## 전체 흐름

1. 사용자가 기존 `.xlsx` 파일을 업로드한다.
2. 원본을 비공개 Storage에 보존하고 파일 해시와 업로드 배치를 생성한다.
3. 기존 어댑터가 파일 종류를 판별하고 세부 실적을 정규화한다.
4. 기준정보 후보 추출기가 정규화된 행과 생산 파일의 CAPA 근거에서 후보를 만든다.
5. 서버가 기존 기준정보와 비교하여 `기존`, `신규`, `충돌`, `오류` 상태를 계산한다.
6. 업로드 검토 화면이 기준정보 후보와 세부 실적을 분리해 표시한다.
7. 관리자가 신규 후보와 ST 값을 승인하고 중복 처리 방식을 선택한다.
8. 서버 RPC가 단일 데이터베이스 트랜잭션으로 기준정보를 생성하고 세부 실적을 연결·등록한다.
9. 하나라도 실패하면 모든 기준정보와 세부 실적 반영을 취소하고 배치·원본·진단 정보는 보존한다.

## 기준정보 후보

### 모델과 라인

- 파일에서 읽은 코드는 앞뒤 공백, 반복 공백과 기존 정규화 규칙을 적용한다.
- 정규화 코드가 기존 활성 레코드와 같으면 기존 ID를 사용한다.
- 코드가 같지만 파일 표기와 기존 명칭이 다르면 `충돌`로 표시하고 관리자 확인을 요구한다.
- 신규 후보의 기본 명칭은 정규화된 코드와 동일하게 제안하며 관리자가 수정할 수 있다.

### 공정

- 허용 코드는 `SPI`, `AOI`, `XRAY`, `ICT`, `ROUTER`다.
- 기존 공정 시드와 연결하며 임의의 신규 공정 코드는 만들지 않는다.
- 허용 목록으로 정규화할 수 없는 공정은 오류로 처리한다.

### 조와 시간대

인식 가능한 기존 파일의 주간·야간 표기를 각각 `DAY`, `NIGHT`로 정규화한다. 알 수 없는 조 표기는 자동 후보로 만들지 않고 오류로 표시한다.

주간 시간대:

| 코드 | 시작 | 종료 | 종료일 보정 |
|---|---:|---:|---:|
| A | 07:30 | 09:30 | 0 |
| B | 09:30 | 13:00 | 0 |
| C | 13:00 | 15:00 | 0 |
| D | 15:00 | 17:00 | 0 |
| E | 17:00 | 19:30 | 0 |

야간 시간대:

| 코드 | 시작 | 종료 | 종료일 보정 |
|---|---:|---:|---:|
| A | 19:30 | 21:30 | 0 |
| B | 21:30 | 01:00 | 1 |
| C | 01:00 | 03:00 | 0 |
| D | 03:00 | 05:00 | 0 |
| E | 05:00 | 07:30 | 0 |

야간 생산일은 조 시작일을 기준으로 한다. 즉, 야간 B~E의 자정 이후 시각도 같은 생산일과 `NIGHT` 조에 속한다.

### 비가동 사유

- 기존 생산 파일에 비가동 시간이 있으나 사유가 없으면 기존 표준 코드 `LEGACY_UNSPECIFIED`를 제안한다.
- 사유 텍스트가 있는 경우 정규화된 코드·명칭 후보를 만들 수 있다.
- 동일 코드의 명칭 충돌은 관리자 확인 전까지 최종 등록을 차단한다.

## ST 후보 계산

생산 파일의 시간대별 CAPA를 ST 근거로 사용한다.

```text
ST(초/개) = 시간대 계획 초 ÷ CAPA
```

- CAPA가 비어 있거나 0 이하이면 ST 후보를 만들지 않고 원본 위치와 함께 경고한다.
- ST 후보는 `모델 + 라인 + 공정`으로 묶는다.
- 각 관측값의 중앙값을 대표 후보로 계산한다.
- 관측값 중 하나라도 중앙값 대비 절대 편차가 5%를 초과하면 `충돌` 상태로 표시한다.
- 충돌이 없으면 중앙값을 소수점 셋째 자리까지 제안한다.
- 충돌 시 관리자는 원본 관측값 하나를 선택하거나 ST를 직접 입력해야 한다.
- 적용 시작일은 해당 그룹이 원본에서 처음 관측된 생산일이다.
- 적용 종료일은 기본적으로 비어 있는 열린 기간이다.
- 기존 ST 유효기간과 겹치면 자동 생성하지 않고 기간 충돌을 표시한다.

검토 화면에는 계산식, 시간대, CAPA, 산출 ST, 최소값, 중앙값, 최대값, 원본 파일·시트·행을 표시한다.

## 세부 실적 변환

### 생산 파일

- 생산일, 조, 시간대, 모델, 라인, 공정, 실제 생산량을 등록한다.
- 비가동 시간과 메모를 보존한다.
- 품질 수치가 없는 생산 행은 생산 차원만 등록한다.

### 품질 파일

- SPI, AOI, X-ray, ICT의 생산일, 조, 모델, 라인, 공정, 투입, OK, NG를 등록한다.
- 시간대가 없는 월간 품질 행은 일별 품질 레코드로 유지하며 임의의 시간대를 지정하지 않는다.
- 불량 유형, 분류와 수량을 품질 레코드에 연결한다.
- 품질 파일에 실제 생산량이 없으면 생산 차원을 임의로 만들지 않는다.

### 원본 추적

각 기준정보 후보, ST 근거와 세부 실적은 최소한 다음 정보를 유지한다.

- 업로드 배치 ID
- 원본 파일명과 파일 해시
- 시트명
- 원본 행 번호
- 파일 종류

## 스테이징과 데이터베이스

기존 `upload_batches`, `upload_rows`를 유지하고 다음 개념을 추가한다.

- 기준정보 후보 스테이징: 엔터티 유형, 정규화 코드, 제안 명칭, 상태, 승인값, 원본 근거
- ST 후보 스테이징: 모델·라인·공정 코드, 관측값, 대표값, 편차 상태, 적용 기간, 승인값
- 배치 승인 정보: 관리자, 승인 시각, 중복 처리 방식

최종 RPC는 다음 순서로 실행한다.

1. 활성 관리자와 배치 소유·상태를 재검증한다.
2. 배치 행을 잠그고 이미 완료된 배치의 재실행을 거부하거나 이전 결과를 반환한다.
3. 승인되지 않은 충돌·오류가 없는지 확인한다.
4. 모델, 라인, 조, 시간대, 비가동 사유, ST 순으로 기준정보를 생성한다.
5. 생성되거나 기존에 존재하는 ID로 스테이징된 세부 실적을 다시 해석한다.
6. 실적 중복 정책을 적용하고 생산·품질·불량·비가동을 등록한다.
7. 배치를 완료 상태로 바꾸고 삽입·교체·건너뜀 수를 반환한다.

모든 단계는 하나의 트랜잭션에서 수행하며 감사 트리거와 기존 RLS를 유지한다. 클라이언트가 임의 ID나 관리자 승인 상태를 위조할 수 없도록 최종 판단은 서버에서 반복한다.

## 검토 화면

업로드 화면에 다음 영역을 제공한다.

1. 파일 정보와 파싱 상태
2. 기준정보 요약: 기존, 신규, 충돌, 오류 수
3. 기준정보 후보 편집 표
4. ST 후보와 산출 근거 표
5. 세부 실적 요약: 신규, 중복, 오류 수
6. 원본 위치가 포함된 상세 진단
7. 관리자 전용 승인 및 최종 반영 영역

9,658개 생산 상세를 한 번에 렌더링하지 않고 요약, 필터와 페이지 단위 조회를 사용한다.

## 오류와 중복 처리

- 필수값, 날짜, 수량, 허용 공정, 조 표기 오류는 원본 위치와 함께 표시한다.
- 해결되지 않은 기준정보 충돌, ST 충돌 또는 행 오류가 있으면 최종 반영을 차단한다.
- 기존 실적 중복은 기본적으로 건너뛰며 관리자가 명시적으로 선택한 경우에만 교체한다.
- 작업자는 중복 교체를 승인할 수 없다.
- 같은 파일 해시와 완료된 배치의 재업로드는 중복으로 안내한다.
- 실패한 배치는 재검토할 수 있지만 완료 배치는 불변으로 유지한다.

## 테스트와 검증

### 파서 및 도메인 테스트

- 보존 원본 5개의 해시와 기존 행수 대조
- 모델, 라인, 주간·야간 조와 시간대 후보 추출
- 일별 품질 행이 임의 시간대를 얻지 않는지 검증
- CAPA 기반 ST 계산, 중앙값과 5% 편차 경계
- 결측·0 CAPA 경고
- 원본 위치 추적

### 저장소 및 데이터베이스 테스트

- 기준정보 의존 순서와 ID 해석
- 기존 기준정보 재사용과 명칭 충돌
- ST 유효기간 중복
- 생산·품질·불량·비가동 연결
- 관리자 전용 승인과 중복 교체
- 중간 오류 시 기준정보와 실적 전체 롤백
- 동일 배치 재실행의 멱등성
- RLS와 감사 로그

### 화면 및 운영 검증

- 작업자 검토 화면과 관리자 승인 화면
- 대용량 페이지 조회
- 기존 5개 파일의 스테이징 및 예상 건수
- production 배포 후 관리자 계정으로 실제 업로드·승인·대시보드 반영 확인

## 제외 범위

- 원본 Excel 파일 수정 또는 덮어쓰기
- 관리자 확인 없는 신규 기준정보 자동 확정
- 파일에 근거가 없는 임의 ST 생성
- 기존 기준정보의 자동 명칭 변경·비활성화
- 허용 목록 밖의 신규 공정 자동 생성
