# SMD 공정 관리 웹 시스템 설계

작성일: 2026-07-28  
상태: 사용자 설계 승인 완료, 구현 계획 작성 전

## 1. 목적

전장 카메라 제조 SMD 공정의 시간대별 실적, 공정 수율, ST 기준 라인 가동률을 하나의 공용 웹 시스템에서 관리한다. 여러 사용자가 동시에 입력하고 조회할 수 있어야 하며, 기존 수기 집계와 분산된 월간 Excel 관리를 줄이는 것이 목표다.

성공 기준은 다음과 같다.

- 작업자가 시간대 실적을 1분 이내에 등록할 수 있다.
- 등록된 데이터가 정상 네트워크 환경에서 5초 이내에 다른 사용자의 화면에 반영된다.
- 모델, 공정, SMD 라인, 기간, 조를 조합해 수율과 가동률을 조회할 수 있다.
- 기존 5종 Excel 파일과 신규 통합 표준 양식을 모두 검증 후 가져올 수 있다.
- 모든 변경의 작업자, 시간, 변경 전후 값을 추적할 수 있다.
- 한국어와 베트남어를 지원한다.

## 2. 시스템 경계

새 시스템은 기존 ACM·ACK 인력현황 앱과 완전히 분리한다.

- 별도 애플리케이션 디렉터리: `smd-process-control`
- 별도 배포 프로젝트
- 별도 Supabase 프로젝트
- 별도 사용자, 권한, 데이터베이스, 파일 저장소

기존 인력현황 앱의 코드, 데이터, 배포 설정은 변경하지 않는다.

## 3. 사용자와 권한

### 작업자

- 시간대별 실적 수기 입력
- 공정 품질 실적 입력
- Excel 파일 업로드 및 저장 전 검증
- 자신이 등록한 당일 데이터 수정. 당일 기준은 `Asia/Bangkok`의 생산일 23:59까지다.
- 대시보드와 상세 조회

### 관리자

- 모든 데이터 등록, 수정, 삭제
- 중복 업로드 데이터의 교체 승인
- 사용자 계정과 역할 관리
- 모델, 공정, 라인, 조, 시간 구간, 비가동 사유 관리
- ST 등록과 적용 기간 관리
- 감사 이력과 업로드 원본 조회

### 조회자

- 대시보드와 상세 데이터 읽기
- Excel 및 PDF 보고서 다운로드
- 데이터 등록, 수정, 삭제 불가

로그인 화면은 사번과 비밀번호만 받는다. 시스템 내부 인증 식별자는 사번과 연결하며, 관리자가 계정을 생성·비활성화한다. Supabase Auth와 Row Level Security를 사용해 역할별 접근을 서버에서 제한한다.

## 4. 기술 구조

- 프런트엔드: React 기반 반응형 웹 앱
- 백엔드: Supabase Auth, PostgreSQL, Realtime, Storage
- 파일 처리: 브라우저에서 1차 구조 분석 후 서버 트랜잭션으로 검증·저장
- 배포: 기존 인력현황 앱과 분리된 독립 배포
- 지원 화면: 현장 PC 우선, 태블릿 대응
- 언어: 한국어와 베트남어 전환

실적 저장 후 관련 테이블의 변경 이벤트를 구독 중인 대시보드에 전달한다. 사용자는 새로고침 없이 최신 집계 결과를 확인한다.

## 5. 기준정보

관리자가 다음 기준정보를 관리한다.

- 모델
- 공정: SPI, AOI, X-ray, ICT, Router
- SMD 라인
- 조: 주간조, 야간조 및 추가 가능한 사용자 정의 조
- 시간 구간: 기본 A~E, 조별 시작·종료 시간 설정
- 비가동 사유: 설비 고장, 모델 교체, 자재 대기 등
- 공정별 수율 목표
- 모델 × 공정 × 라인별 ST

시간 구간과 비가동 사유는 삭제 대신 비활성화할 수 있어야 한다. 과거 실적이 참조하는 기준정보는 물리적으로 삭제하지 않는다.

## 6. 데이터 모델

### 사용자와 기준정보

- `profiles`: 사번, 이름, 역할, 언어, 활성 상태
- `models`: 모델 코드와 명칭
- `processes`: 공정 코드와 명칭
- `lines`: 라인 코드와 명칭
- `shifts`: 조 명칭과 활성 상태
- `time_slots`: 조, 구간 코드, 시작·종료 시간, 종료일 오프셋, 순서
- `downtime_reasons`: 비가동 사유와 분류
- `yield_targets`: 공정, 선택 모델, 적용 기간, 목표 수율. 모델이 비어 있으면 공정 기본 목표다.

### ST

- `standard_times`: 모델, 공정, 라인, 초/개, 적용 시작일, 적용 종료일

같은 모델·공정·라인에서 적용 기간이 겹치는 ST는 저장할 수 없다. 실적일에 유효한 ST가 하나만 선택되도록 데이터베이스 제약과 서버 검증을 함께 적용한다.

### 실적과 품질

- `production_records`: 날짜, 조, 시간 구간, 라인, 모델, 공정, Input, 실적, 비고, 입력 출처
- `quality_records`: 날짜, 조, 선택 시간 구간, 라인, 모델, 공정, Input, OK, NG, 연결 실적
- `defect_records`: 품질 실적, 불량 유형, 가성·진성·폐기 구분, 수량
- `downtime_records`: 실적, 비가동 시작·종료 또는 분, 사유, 비고

`production_records`는 생산량과 가동률의 원본이고, `quality_records`는 검사 공정 수율의 원본이다. 같은 업로드 행에 생산량과 품질 수치가 함께 있으면 두 레코드를 생성해 연결한다.

시간대 실적의 중복 키는 `날짜 + 조 + 시간 구간 + 라인 + 모델 + 공정`이다. 품질 원본에 시간 구간이 없으면 `time_slot_id`를 비운 일 단위 품질 실적으로 저장하며, 동일 날짜·조·라인·모델·공정의 일 단위 레코드가 중복 키가 된다.

### 업로드와 감사

- `upload_batches`: 파일명, 원본 저장 위치, 업로더, 파일 형식, 처리 상태, 건수
- `upload_rows`: 원본 행, 변환 결과, 오류 코드, 대상 레코드
- `audit_logs`: 대상 테이블, 대상 ID, 작업 유형, 변경 전후 값, 사용자, 시각

원본 Excel 파일은 전용 Storage 버킷에 보관한다. 데이터 삭제가 승인돼도 업로드 원본과 감사 이력은 유지한다.

## 7. 계산 규칙

### 수율

`공정 수율(%) = OK ÷ Input × 100`

- Input이 0이면 `계산 불가`로 표시한다.
- OK가 Input보다 크면 저장을 차단한다.
- 공정·모델별 목표가 있으면 가장 구체적인 목표를 적용하고, 없으면 공정 기본 목표를 적용한다.

### 순가동 가능시간

`순가동 가능시간(초) = 시간 구간 계획시간(초) − 비가동시간(초)`

- 비가동시간이 계획시간보다 크면 저장을 차단한다.
- 비가동 기록이 여러 건이면 합산한다.

### 라인 가동률

`라인 가동률(%) = 실적 수량 × 실적일 유효 ST(초/개) ÷ 순가동 가능시간(초) × 100`

- ST가 없으면 실적은 저장하고 가동률은 `ST 미등록`으로 표시한다.
- 순가동 가능시간이 0이면 `계산 불가`로 표시한다.
- 100% 초과값은 그대로 표시하고 입력값 또는 ST 검토 대상으로 표시한다.
- 과거 실적은 실적일에 유효했던 ST로 계산한다. ST 변경이 과거 실적의 기준을 임의로 바꾸지 않도록 적용 기간을 버전 관리한다.

## 9. Excel 호환과 통합 표준 양식

초기 호환 대상은 `SMD 공정 관리` 폴더의 다음 5종이다.

1. AOI 월간 수율 파일
2. ICT 월간 수율 파일
3. SPI 월간 수율 파일
4. X-ray 월간 수율 파일
5. SMD 공정별 시간대 실적 파일

기존 파일에서 다음 정보를 표준 데이터로 변환한다.

- 날짜와 조
- 모델과 라인
- 공정
- Input, Output 또는 OK, NG
- 불량 상세
- 시간대별 CAPA와 실적
- 비가동시간과 비고

새 통합 표준 양식은 한 행을 하나의 `날짜 + 조 + 시간 구간 + 라인 + 모델 + 공정` 실적으로 정의한다. 필수 열은 다음과 같다.

- 날짜
- 조
- 시간 구간
- 라인
- 모델
- 공정
- Input
- 실적
- OK
- NG
- 비가동시간(분)
- 비가동 사유
- 비고

품질 불량 상세는 별도 시트에서 실적 행 식별자, 불량 유형, 구분, 수량으로 입력한다. 양식 버전을 파일 안에 기록하고, 지원하지 않는 버전은 업로드 전에 차단한다.

## 10. 저장과 충돌 처리

수기 입력과 파일 업로드는 모두 서버 트랜잭션으로 저장한다.

- 필수값 누락, 음수, 잘못된 관계를 저장 전에 차단한다.
- 중복 레코드는 작업자가 덮어쓸 수 없다.
- 관리자는 기존값과 신규값을 비교한 뒤 교체할 수 있다.
- 업로드는 검증 단계와 저장 단계를 분리한다.
- 업로드 일부 행에 오류가 있으면 전체 검증 결과를 먼저 표시하고 자동으로 부분 저장하지 않는다.
- 저장 중 오류가 발생하면 해당 배치의 데이터 변경을 롤백한다.
- 동시에 같은 레코드를 수정하면 최신 버전을 비교해 충돌을 알리고 재확인을 요구한다.

## 11. 보안과 운영

- 모든 업무 테이블에 Row Level Security 적용
- 관리자 기능은 관리자 역할만 호출 가능
- Storage 원본 파일은 인증 사용자에게도 역할별 접근 제한
- 비밀번호와 인증 토큰을 업무 테이블에 저장하지 않음
- 관리자 작업과 삭제는 감사 이력 필수
- 비활성 사용자 로그인 차단
- 데이터베이스 백업과 원본 파일 보존 정책 적용

## 13. 구현 범위 제외

첫 버전에는 다음을 포함하지 않는다.

- 설비 PLC 또는 MES와의 자동 연동
- 모바일 전용 앱
- 자동 생산 계획 수립
- AI 불량 원인 예측
- 이메일 또는 메신저 자동 알림

이 항목들은 기본 데이터 품질과 현장 사용성이 확인된 후 별도 단계에서 검토한다.
